# WusicPlayer 多语言 (i18n)

## 概览

多语言基于 Qt 标准翻译机制:

```
源码 tr("...")  ->  lupdate 提取  ->  .ts (XML 翻译源)
                                        │  Qt Linguist / 手写翻译
                                        ▼
运行时 QTranslator  ←───────────────  .qm (lrelease 编译)
```

- 所有用户可见字符串在源码中用 `tr("...")` 标记(见下方「字符串标记规范」)。
- 翻译文件: `translations/wusicplayer_<locale>.ts`,编译产物 `wusicplayer_<locale>.qm`。
- 程序启动时按 `LanguageSettings::locale()` 加载可执行文件旁 `translations/` 目录下对应 `.qm`。
- 语言切换在设置面板「Language」页,切换后**重启生效**(不做运行时热切换)。

## 架构

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| `LanguageSettings` | `src/core/config_manager/language_settings.{h,cpp}` | 单例;保存/恢复当前 locale(JSON 键 `language.locale`);按系统 locale 自动检测默认值 |
| `LanguageSettingsPage` | `src/view/settings_panel/language_settings_page.{h,cpp}` | 设置面板「语言」页;English / 简体中文 下拉切换 |
| `main.cpp` | `src/main.cpp` | `load_all()` 后按 locale 加载 `.qm` 并 `installTranslator`(有 `[i18n]` 日志) |
| CMake 集成 | 根 `CMakeLists.txt` + `src/CMakeLists.txt` | `lupdate` 提取、`lrelease` 编译、`.qm` 部署到可执行文件旁 |

### 构建目标

- `cmake --build build/debug --target translations_update` — 运行 `lupdate` 更新 `.ts`(新增/删除条目,保留已有翻译)
- `cmake --build build/debug` — `translations` 目标(默认 ALL)自动运行 `lrelease` 编译 `.qm`,并复制到 `$<TARGET_FILE_DIR:WusicPlayer>/translations/`

## 日常编辑流程

新增或修改一个用户可见字符串后:

1. **源码标记**: 在 UI/消息文本外包 `tr("...")`。
   ```cpp
   // 好
   auto* btn = new QPushButton(tr("Apply"), this);
   QMessageBox::information(this, tr("Warning"), tr("Please choose a valid value!"));
   // 坏(不会被提取)
   auto* btn = new QPushButton("Apply", this);
   ```

2. **更新 .ts**:
   ```bash
   cmake --build build/debug --target translations_update
   ```
   `lupdate` 会扫描 `src/` 下的 `tr()` 调用,把新字符串追加到 `translations/wusicplayer_zh_CN.ts`(保留已有翻译,不重复)。

3. **翻译**: 用 **Qt Linguist**(`linguist` / `linguist6`)打开 `.ts` 逐条翻译;或直接编辑 `.ts` 的 `<translation>` 标签。
   > 注意: 未填翻译的条目会被 `lrelease` **丢弃**(不进入 `.qm`),因此必须填写翻译后才生效。

4. **编译部署**:
   ```bash
   cmake --build build/debug
   ```
   触发 `lrelease` → 生成 `build/debug/translations/wusicplayer_zh_CN.qm` → 自动复制到 `build/debug/src/translations/`(可执行文件旁)。

5. **验证**: 启动程序(系统 locale 或设置面板已选中文),日志出现 `[i18n] translation loaded: .../wusicplayer_zh_CN.qm`;切英文(`en_US`)时 UI 回退显示 source 原文。

## 支持更多语言

要新增一种语言(如日语 `ja_JP`),按以下步骤:

### 1. 生成新语言 .ts

**方案 A(推荐, 全新语言)** — 在根 `CMakeLists.txt` 的 `WUSIC_TS_FILES` 中加入新文件:

```cmake
set(WUSIC_TS_FILES
    "${WUSIC_TRANSLATIONS_DIR}/wusicplayer_zh_CN.ts"
    "${WUSIC_TRANSLATIONS_DIR}/wusicplayer_ja_JP.ts"   # 新增
)
```

然后:

```bash
mkdir -p translations
cmake --build build/debug --target translations_update
# 重新 configure 使新文件进入 lrelease 依赖
cmake -S . -B build/debug
```

`lupdate` 会为 `ja_JP` 创建全新的 `.ts`(所有条目待翻译)。

**方案 B(基于已有翻译)** — 复制现有 `.ts` 作为起点(适合与 zh_CN 相近语系或复用翻译):

```bash
cp translations/wusicplayer_zh_CN.ts translations/wusicplayer_ja_JP.ts
```

> 复制前先把原 `.ts` 的 `<translation>` 内容清空,避免误把中文当成日语提交。

### 2. 翻译

用 Qt Linguist 打开新 `.ts`,逐条填写翻译(注意 `%1` 占位符必须保留、`&` 助记符按平台惯例处理)。

### 3. 泛化 CMake 部署(一次性)

当前 `translations` 目标的复制命令硬编码了 `wusicplayer_zh_CN.qm`。新增语言后需改为遍历所有 `.qm`。推荐方式:在根 `CMakeLists.txt` 用 `file(GLOB)` 收集,后续加语言**无需再改 CMake**:

```cmake
# 编译 .qm(每个 .ts 一个)
add_custom_command(
    OUTPUT ${WUSIC_QM_FILES}
    COMMAND ${CMAKE_COMMAND} -E make_directory "${WUSIC_QM_DIR}"
    COMMAND ${QT_LRELEASE_EXECUTABLE} ${WUSIC_TS_FILES}
            -qm "${WUSIC_QM_DIR}/"
    DEPENDS ${WUSIC_TS_FILES}
    COMMENT "Compiling translations to .qm"
)
# 部署: 把编译出的所有 .qm 复制到可执行文件旁
file(GLOB WUSIC_QM_FILES "${WUSIC_QM_DIR}/*.qm")
add_custom_target(translations ALL
    DEPENDS ${WUSIC_QM_FILES}
    COMMAND ${CMAKE_COMMAND} -E make_directory "$<TARGET_FILE_DIR:WusicPlayer>/translations"
    COMMAND ${CMAKE_COMMAND} -E copy_if_different ${WUSIC_QM_FILES}
            "$<TARGET_FILE_DIR:WusicPlayer>/translations/"
    COMMENT "Deploying .qm next to the executable"
)
```

> `lrelease` 支持 `-qm <dir>/` 一次输出多个 `.qm` 到目录。

### 4. 语言设置页加入口

`LanguageSettingsPage` 的 `QComboBox` 添加新语言项(数据为 locale 字符串,必须与 `.qm` 文件名一致):

```cpp
m_cb_language->addItem(QStringLiteral("日本語"), QStringLiteral("ja_JP"));
```

### 5. 默认检测(可选)

`LanguageSettings::detect_system_locale()` 目前只区分中文/其他。要按系统语言自动选新语言,扩展它:

```cpp
if (sys.language() == QLocale::Japanese) {
    return QStringLiteral("ja_JP");
}
```

### 6. 运行时

`main.cpp` 已按 `<locale>.qm` 泛化加载,无需改动。加载不到的 locale 会回退到英文(source 原文)。

## 注意事项 / 踩坑

- **Qt5 wrapper 陷阱**: 系统 `/usr/bin/lupdate` 可能是 Qt5 wrapper,运行时报 `could not exec '/usr/lib/qt5/bin/lupdate'`。根 `CMakeLists.txt` 已通过 `find_program(... HINTS ... /usr/lib/qt6/bin)` 优先 Qt6 工具。
- **改 HINTS 后需清缓存**: 修改 `find_program` 的路径后,CMake 会沿用缓存旧值,必须清掉重新 configure:
  ```bash
  cmake -S . -B build/debug -U QT_LUPDATE_EXECUTABLE -U QT_LRELEASE_EXECUTABLE
  ```
- **空翻译会被丢弃**: 未填 `<translation>` 的条目不进入 `.qm`(空 `.qm` 只有 26 字节)。
- **首次生成 .ts**: `lupdate` 需要 `translations/` 目录存在,先 `mkdir -p translations`。
- **lupdate 警告**: `Ignoring definition of undeclared qualified class` 是无 `Q_OBJECT` 类用了 `tr()` 的无害警告;`Class 'X' lacks Q_OBJECT macro` 提示该类 `tr()` 回退到全局 `QCoreApplication::translate`,翻译仍可提取,但不建议长期保留。
- **部署时序**: `.qm` 复制放在 `translations` 目标的 `COMMAND` 里(每次构建都执行);放在 `POST_BUILD` 只在链接时触发,`.qm` 更新后不会自动复制。
- **语言切换**: 需重启生效,`QTranslator` 在 `main()` 中随主函数生命周期存活,不要放在局部作用域提前析构。
